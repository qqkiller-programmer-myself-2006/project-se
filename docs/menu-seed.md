# Menu Seed — เมนูอาหารร้านป้าอ้อ (60 จาน)

สคริปต์ `apps/api/src/seedMenu.ts` เติมเมนูอาหาร 60 จานของ **ร้านป้าอ้อ**
แบบ idempotent ผ่าน Store/API layer เท่านั้น (ไม่ใช้ SQL/Prisma ตรง)

เมนูเครื่องดื่ม 18 รายการ (หนูนุ้ย ชาใต้) ไม่อยู่ในสคริปต์นี้ — มากับ migration
`db/migrations/016_seed_noonui_cha_tai.sql`

## แหล่งความจริงคือชุดรูป

รายการ 60 จานสร้างตาม **ชุดรูปเมนูอาหาร** ที่อัปขึ้น Cloudflare R2 แล้ว
(key `food-menu/NN-slug.png`) ลำดับเมนูคือเลขนำหน้าไฟล์ และ slug คือชื่อไฟล์

ถ้าจะเพิ่ม/เปลี่ยนจาน ให้ **อัปรูปก่อน** แล้วค่อยแก้ `FOOD_DEFINITIONS` ให้ตรงกับชื่อไฟล์
ถ้าเขียนรายการเมนูแยกจากรูป สองอย่างจะหลุดกันเงียบ ๆ (เคยเกิดแล้ว: รูปพัง 56 จาก 59 จาน)

เทสต์กันไว้สองชั้น:

- `apps/api/tests/menu-seed.test.ts` — เลขไฟล์ตรงลำดับจาน และ (เมื่อมีโฟลเดอร์รูปในเครื่อง)
  รูปทุกใบมีอยู่จริง
- `apps/web/tests/demo-food-images.test.ts` — fixture ฝั่งเว็บใช้รายการเดียวกัน

ต้นฉบับรูป (~140 MB) **ไม่อยู่ใน git** — อยู่ใน `apps/web/public/food-menu/` เฉพาะเครื่องที่ทำงานกับรูป
เทสต์ที่ต้องเห็นไฟล์จริงจะข้ามเองเมื่อไม่มีโฟลเดอร์นี้

## ⚠️ คำเตือนความปลอดภัย (อ่านก่อนรันทุกครั้ง)

- **ต้องมี `DATABASE_URL` ก่อนรัน** — สคริปต์ใช้ `createStoreFromEnv()` ซึ่งโยน error
  ทันทีถ้าไม่มี (โหลดจาก `.env` ของ project ให้อัตโนมัติ)
- **ห้ามรันตรงใน production** — seed เขียนข้อมูลจริงและสร้าง audit ทดสอบกับฐาน dev/staging
  ก่อนเสมอ และต้องมี backup
- สคริปต์ปฏิเสธเมื่อ `NODE_ENV=production` เว้นแต่ตั้งใจจริงด้วย `MENU_SEED_ALLOW_PRODUCTION=true`
- **ห้ามพิมพ์ secret ลง log** — สคริปต์พิมพ์เฉพาะสรุปจำนวน
- สคริปต์ **ไม่รันเองตอน start server**

## วิธีรัน

```powershell
npx tsx apps/api/src/seedMenu.ts --username owner1
```

- `--username` (หรือ `MENU_SEED_USERNAME`) คือบัญชีพนักงานที่จะถูกบันทึกเป็นผู้ทำใน audit
  ต้องมีอยู่จริง รูปแบบ `a-z 0-9 _ . -` ยาว 3–32 — **ไม่ต้องใช้รหัสผ่าน**
- base URL ของรูปมาจาก `MENU_SEED_PUBLIC_ASSET_BASE_URL` ค่า default คือ R2 public URL
  ของ bucket ร้าน ค่าที่ตั้งเองต้องเป็น `http://`/`https://` เท่านั้น (API ไม่รับ path สัมพัทธ์)

ผลลัพธ์ที่พิมพ์:

```
[menu-seed] ร้านป้าอ้อ: menus=60 created=… skipped=… imagesRepaired=… placeholdersRetired=… groupsCreated=… optionsCreated=…
```

## สิ่งที่สคริปต์ทำกับข้อมูลเดิม

| กรณี | ทำอะไร |
|---|---|
| จานในแผนยังไม่มี | สร้างใหม่ พร้อมกลุ่มตัวเลือก ขนาด + เพิ่มไข่ |
| จานในแผนมีแล้ว (ชื่อ + หมวดตรงตัว) | ไม่สร้างซ้ำ เติมเฉพาะกลุ่ม/ตัวเลือกที่ขาดตามชื่อ |
| จานในแผนมีแล้ว แต่รูปไม่ตรง | **แก้เฉพาะ `imageUrl`** — ราคา คำอธิบาย สถานะที่ร้านแก้เองไม่ถูกทับ |
| จานนอกแผนที่รูปชี้ `https://example.com/` | **archive** (ของตกค้างจาก seed รุ่นแรก รูปโหลดไม่ได้แน่นอน) |
| จานนอกแผนอื่น ๆ (ร้านเพิ่มเอง) | ไม่แตะ |
| จานที่ archive แล้ว | ข้าม ไม่ sync ลูก |

archive ย้อนคืนได้จากหน้าจัดการเมนูและมี audit — ไม่มีการลบข้อมูล

รันซ้ำได้ปลอดภัย: ครั้งที่สองควรได้ `created=0 imagesRepaired=0 placeholdersRetired=0`

## ไม่มีกลุ่มตัวเลือก "เนื้อสัตว์"

ชื่อจานระบุเนื้อไว้แล้ว (ข้าวผัดหมู กับ ข้าวผัดไก่ เป็นคนละเมนู) ถ้ามีกลุ่มเนื้อสัตว์
ลูกค้าจะสั่ง "ข้าวผัดหมู" แล้วเลือก "ไก่" ได้ ซึ่งขัดกันเอง
